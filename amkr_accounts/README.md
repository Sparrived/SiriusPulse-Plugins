# AMKR 账号资源

通过群聊命令读取 AMKR 的全局账号资源与用量，并可用状态监控查看渠道健康；用本地 Pillow 生成深蓝/青色霓虹看板，沿框架图片消息链路发送到当前群。无需 LLM、Playwright 或浏览器，不新增依赖。

[效果预览与权威文档](https://sirius-pulse-docs.vercel.app/extensions/amkr-accounts)

## 启用

1. 使用 Sirius Pulse **1.3.0+**，确保外部 `plugins/` 子模块已初始化且包含本目录。
2. 在 Sirius Pulse 全局设置中配置 AMKR 的服务端地址 `amkr_base_url` 和管理员凭据 `amkr_local_api_key`；也可以通过 `SIRIUS_AMKR_BASE_URL` / `SIRIUS_AMKR_API_KEY` 注入。复用框架的 `env:NAME` 间接凭据解析，不要在本插件设置或群消息中填写 Key。
3. AMKR 必须支持 **`GET /api/cpa-accounts`**。先在 AMKR 自己的面板配置 CPA 实例，或添加可识别的订阅供应商（如 OpenCode Go / Command Code）。此插件不增加或修改账号。若要使用 `/amkr status`，AMKR 需 **6.9.0+** 并开启 `webui_enabled`（状态监控接口为 `GET /ui/status-monitor.json`）。
4. 在 WebUI 的插件管理启用「**AMKR 账号资源**」；所有群成员均可查询，必要时重载插件或重启人格。旧部署若曾配置 `permissions.developer_only=true`，需在插件权限设置中关闭该覆盖。
5. 图片优先使用系统中文字体（Windows 微软雅黑、Linux Noto Sans CJK / 文泉驿、macOS 苹方），其次使用源码树中的已有中文字体。数字与 ID 优先使用 Cascadia Code；Linux 可将该开源字体安装到 `/usr/local/share/fonts/cascadia-code/CascadiaCode.ttf`，Docker 可持久化到 `/app/data/fonts/cascadia-code/CascadiaCode.ttf`。缺少等宽字体时回退中文字体，不影响查询；无需 Chromium。

默认从人格 `work_path`（或 PluginDataStore）推导全局目录：`data/personas/<persona>` → `data`；其他布局使用人格目录。若宿主另行指定了不同的全局目录，在插件设置 `global_data_path` 填写**全局数据目录的绝对路径**。留空适用于标准布局；配置在服务端读取，不写回任何文件。

## 指令

| 指令 | 行为 |
| --- | --- |
| `/amkr` 或 `/amkr help` | 显示使用说明，不发起请求 |
| `/amkr account` | 一张长图展示全部 CPA 账号、订阅资源和失败/空实例 |
| `/amkr status [小时]` | 渠道健康矩阵、请求趋势与错误归因，默认近 24 小时 |
| `/amkr account all` | 同上 |
| `/amkr account cpa-main/0` | 按 CPA 完整 ID（`实例ID/auth_index`）精确查询 |
| `/amkr account opencode-go/main` | 按订阅 ID（`provider_id/key_name`）精确查询 |
| `/amkr account 主力账号` | 按唯一名称精确匹配；也支持邮箱或订阅账号、Key 的名称 |
| `/amkr account "我的 主力账号"` | 支持带空格的名称，也可直接输入空格名称 |
| `/amkr account cpa-main` | 查看某个 CPA 实例的所有账号，也支持实例显示名称 |

默认一次发送包含**全部匹配资源**的横向密集看板，不需要页码。**一个账号占一条完整横行**：左侧显示一次身份信息，右侧四列排列额度窗口与数值项；窗口较多时仅在该行内部增加高度，不拆成重复账号卡片、不丢弃窗口。单图最多 64 个账号，高度最多 20000 像素，超过上限请指定账号或实例缩小查询。名称重复时返回候选完整 ID；未找到不会回退到全量查询。ID 优先于名称匹配，裸 `auth_index` 不作为跨实例账号 ID。

“指定账号”只表示查看用量，**不会切换推理所用账号**。

## 状态监控

`/amkr status [小时]` 读取 AMKR 6.9+ 的状态监控接口（`GET /ui/status-monitor.json?group_by=provider`），默认近 24 小时，小时数取 1–8760。

- 概览：请求数、成功率、平均首字、缓存命中率、当前 RPM 和综合健康分。
- 请求趋势：每桶请求量，失败量以红色叠加；同时展示峰值与窗口起止。
- 错误归因：同一窗口内非 2xx 状态码的计数，最多列出 5 个。
- 渠道健康矩阵：按供应商一行，显示请求数、成功率、平均首字、缓存命中与健康分；最多 60 行，AMKR 按请求量排序并回传 `rows_truncated`，图中明确提示还有多少行未显示，不静默丢行。
- 健康分与 AMKR 状态监控同一口径：成功率 60% + 首字 20%（≤1.5s 满分、≥8s 零分）+ 缓存 20%（命中 30% 满分）。请求数少于 3 显示“样本不足”，0 显示“无流量”；分档 ≥80 健康、50–79 注意、<50 异常。
- 窗口与时间固定 **UTC+08:00**。窗口内没有请求时显示“窗口内没有请求”，不把 0/0 伪装成 0%，也不把无流量当作故障。

## 图片与读数

- 汇总：所选 CPA 账号数、订阅数、剩余额度 ≤20% 的资源数、读取异常数。
- 卡片：脱敏名称、完整选择 ID、来源/供应商、套餐、状态、额度窗口及模型组、重置时刻、数值项，CPA 账号附成功/失败请求计数（上游有提供时）。
- **轨道环表示剩余比例，不是已用比例**：`remaining=0.58` 显示剩余 58%；百分比向下取整，不把接近 100% 误报成满额。
- `source=passive` 标识为“被动快照”，`quota` 标识为“现场查询”。没有窗口或无效比例显示未知，不当作 0% 或无限额度。
- 时间使用 **UTC+08:00**；CPA 重置时刻扣除 `server_time_offset_ms`。`fetched_at` 只表示整轮读取结束，不保证被动快照也是此刻采集。
- `summary` 只展示上游数值和单位/币种，不猜总额度、不换算成本。窗口与数值项独立保留。
- 实例/订阅读取失败、部分订阅用量失败、额度查询失败会明确提示；上游原始错误内容不发到群里。

## 权限与安全

- **所有群成员均可查询**，无需开发者身份。不让自然语言意图识别调用；私聊不能查询，限流与群组访问范围仍然生效。
- 资源是 **AMKR 全局数据**，不是某个人格工作空间；工作区头无法提供账号隔离。请仅在可信群中使用，并按框架权限管理限制群组/用户。图片脱敏不等于所有运维信息均可公开。
- 账号查询的唯一 AMKR 请求是管理员凭据认证的 `GET /api/cpa-accounts`；不请求带管理密钥明文的 `/api/cpa-instances`，不调用 `/v1`、探测、重置、编辑或删除接口，也不放宽 Sirius 的 `/amkr` 公共反代。
- `/amkr status` 另发一条只读请求 `GET /ui/status-monitor.json`，同样使用管理员凭据；不访问 `/metrics` 明细、不写状态、不触发更新。响应最多 8 MiB、最多 60 行渠道与 500 个趋势点，超出会明确报错。当前固定按供应商（`provider_id`）分组，不展示上游 Key 名。
- 原始账号响应、身份/内部地址、`signals`、`status_message`、错误正文不写磁盘、不交给 LLM。按显示字段白名单投影，邮箱掩码，过滤已知 Key/token 格式及当前管理凭据；别名不应自行包含任意其他秘密。
- PNG 与消息用的 Base64 均在内存中生成，不产生账号图片缓存或临时文件；NapCat 不必与 Sirius 共用磁盘。
- 单实例查询互斥；框架默认限流每分钟 2 次、每小时 30 次。无后台轮询，无自动重试。**每次查询（包括指定账号）仍会让 AMKR 对所有上游重新扇出**；没有服务端单账号查询。
- 总等待最多 75 秒（AMKR 自身预算 60 秒），响应最多 4 MiB，资源最多 2000 项，单账号最多 128 个额度窗口；状态查询最多 45 秒、8 MiB。超限会明确报错，不偷偷截断。

## 常见问题

- **401/403**：检查全局管理员 Key；工作空间面板 Key、推理 Key、受限访问 Key 均不能读全局账号资源。
- **404**：部署的 AMKR 太旧，或服务端基址指向了 `/v1`/面板页面而非 AMKR 根地址（允许自定义反代前缀）。
- **`/amkr status` 404**：AMKR 低于 6.9.0，或未开启 WebUI（`webui_enabled`）；状态监控接口挂在 `/ui/` 下。
- **超时/读取失败**：在 AMKR 面板检查 CPA 实例、管理凭据、订阅端点及额度提供者。某一实例失败不会阻止其余资源显示。
- **缺失额度**：CPA 未提供额度/未装额度插件时可能没有窗口；没有窗口不代表余额耗尽。
- **字体问题**：安装系统 Noto Sans CJK 或确保源码树已有中文字体可用。
